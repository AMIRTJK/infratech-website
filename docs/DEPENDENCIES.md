# Зависимости: разбор и обоснование

Документ отвечает на три вопроса: что взято из `package.json` предыдущего проекта (`interlink-front`), что не взято и почему, и что добавлено заново под новую архитектуру.

**Пакеты пока не установлены.** Это спроектированный список для следующего этапа: `package.json` обеих частей уже содержит его, `npm install` выполняется вместе с началом разработки.

Общие критерии отбора:

1. **Нужен для информационного сайта**, а не для CRM или внутренней системы.
2. **Совместим** с Next.js App Router / React 19 / отдельным Node-бэкендом.
3. **Оправдывает свой вес** — ESM, tree-shaking, разумный размер (`AGENTS.md` §16, `PERFORMANCE.md` §14).
4. **Не дублирует** то, что уже даёт платформа или фреймворк.

## 1. Что перенесено из старого проекта

| Пакет | Куда | Зачем в новом проекте |
|---|---|---|
| `react`, `react-dom` | `client` | Ядро UI. Версия 19 — как в исходном проекте |
| `typescript` | обе части | Строгая типизация, `strict: true` в обеих частях |
| `@tanstack/react-query` | `client` | Клиентские запросы и мутации: форма обратной связи, «показать ещё», фильтры. Кэш и состояние запроса не пишутся руками. **Взята v5, а не v4**, как в старом проекте: новый проект не связан старым кодом, v5 легче и с более чистым API (`placeholderData: keepPreviousData`, `gcTime`, `useSuspenseQuery`) |
| `lucide-react` | `client` | Иконки как SVG-компоненты, импорт по одной. Иконочный шрифт или PNG-набор были бы тяжелее |
| `tailwindcss` | `client` | Основной инструмент стилизации, генерируется только используемое |
| `tailwind-merge` | `client` | Разрешает конфликты Tailwind-классов в `cn()`. В старом проекте лежал в зависимостях, но не использовался — здесь применяется по назначению |
| `eslint`, `eslint-config-prettier`, `prettier` | обе части | Линт и единый формат кода |
| `typescript-eslint`, `@eslint/js` | `server` | Флэт-конфиг ESLint для TypeScript вне экосистемы Next |
| `@types/node`, `@types/react`, `@types/react-dom` | по месту | Типы окружения |

Инструментальные скрипты старого проекта (`dev`, `build`, `lint`, `test`, `preview`) перенесены по смыслу: `dev`/`build`/`start`/`lint`/`typecheck`/`format` есть в обеих частях, `test` — на сервере (на клиенте тестового окружения пока нет, как и в исходном проекте).

## 2. Что не перенесено

### 2.1. Специфика CRM и внутренней системы

| Пакет | Почему не переносим |
|---|---|
| `antd`, `@ant-design/icons` | Тяжёлый UI-кит под сложные административные интерфейсы: таблицы, формы, реестры. Для публичного сайта это сотни килобайт и чужой визуальный язык вместо фирменного стиля организации. Стилизуем Tailwind + собственные компоненты в `shared/ui` (`AGENTS.md` §14) |
| `ckeditor5`, `ckeditor5-premium-features`, `@ckeditor/ckeditor5-react` | Текстовый редактор нужен тем, кто **создаёт** документы. Посетитель сайта ничего не редактирует. Плюс премиум-часть — платная лицензия |
| `xlsx` | Экспорт таблиц в Excel — сценарий внутренней системы |
| `mammoth` | Конвертация `.docx` — сценарий документооборота |
| `pdfjs-dist`, `react-pdf`, `@types/pdfjs-dist` | Просмотр PDF в приложении. Если сайту понадобится отдать документ, браузер откроет его сам по ссылке |
| `recharts` | Графики и дашборды. На информационном сайте их нет; появится один — сделаем SVG или подключим точечно и лениво |
| `laravel-echo`, `pusher-js` | WebSocket-канал для чата и живых уведомлений, завязанный на Laravel-бэкенд старого проекта. Здесь бэкенд свой и живых данных нет |
| `qrcode`, `@types/qrcode` | Генерация QR-кодов — прикладной сценарий старого проекта. Понадобится — добавим тогда, генерировать лучше на сервере |
| `react-toastify` | Уведомления-тосты нужны интерфейсу с множеством действий. Форме обратной связи достаточно состояния прямо в форме. Пакет к тому же помечен как устаревший |

### 2.2. Дублирует то, что даёт Next

| Пакет | Чем заменён |
|---|---|
| `react-router`, `react-router-dom` | Маршрутизация в Next — файловая (App Router). Отдельный роутер несовместим с ней по смыслу |
| `vite`, `@vitejs/plugin-react-swc`, `vite-plugin-compression`, `@tailwindcss/vite` | Сборку берёт на себя Next; сжатие в продакшене отдаётся обратному прокси или платформе хостинга |
| `terser` | В старом проекте лежал неиспользуемым (минификация шла через esbuild). Next минифицирует сам |
| `autoprefixer`, `postcss` | Tailwind 4 подключается плагином `@tailwindcss/postcss` и не требует ручного автопрефиксера |
| `@fontsource/inter` | Шрифты подключаем через `next/font`: самохостинг, `display: swap`, автоматические fallback-метрики против CLS (`PERFORMANCE.md` §12). Отдельный пакет шрифта не нужен |
| `eslint-plugin-react-hooks`, `eslint-plugin-react-refresh`, `globals` | Входят в `eslint-config-next` |

### 2.3. Решения, которые стоит знать

| Пакет | Решение | Обоснование |
|---|---|---|
| `axios` | **Не переносим** (по умолчанию) | В Next серверные запросы идут через `fetch`, потому что именно он интегрирован с кэшем и `revalidate`; axios эту интеграцию не получает, а на клиенте добавляет ~13 КБ поверх нативного `fetch`. Планируется тонкая обёртка в `client/src/shared/api` (базовый URL, конверт ответа, таймаут, обработка ошибок) — это несколько десятков строк. **Решение обратимо:** если понадобятся перехватчики, прогресс загрузки или отмена в сложных сценариях, `axios` добавляется в `client` одной строкой |
| `framer-motion` (`motion`) | **Не переносим сразу, кандидат** | Анимации появления и параллакс на лендинге чаще всего делаются CSS-переходами и `IntersectionObserver`. Библиотека добавляется, когда появится сценарий, который CSS не покрывает, и не должна попадать в initial-граф (`PERFORMANCE.md` §15) |
| `stylelint`, `stylelint-config-standard` | **Не переносим, кандидат** | При стилизации утилитами Tailwind собственных CSS-файлов почти нет. Если `shared/styles` разрастётся — добавим |
| `eslint-plugin-prettier` | **Не переносим** | Prettier запускается отдельной командой, а не через линт: так быстрее линт и понятнее вывод. Конфликты правил снимает `eslint-config-prettier` |

## 3. Что добавлено заново

### 3.1. `client`

| Пакет | Роль | Обоснование |
|---|---|---|
| `next` | Фреймворк | Серверные компоненты и SSG/ISR дают готовый HTML — главное требование по скорости и SEO. Плюс маршрутизация, `next/image`, `next/font`, метаданные и `sitemap`/`robots` из коробки |
| `clsx` | Условная склейка классов | Пара к `tailwind-merge` в утилите `cn()`; меньше килобайта |
| `@tailwindcss/postcss` | Подключение Tailwind 4 | Замена `@tailwindcss/vite` для сборки Next |
| `@next/bundle-analyzer` | Анализ бандла | Замена `rollup-plugin-visualizer` из старого стека: контроль веса — обязательная часть перф-процесса (`PERFORMANCE.md` §3.1) |
| `eslint-config-next` | Правила линта | Включает `react-hooks`, `react-refresh` и правила Core Web Vitals |
| `@eslint/eslintrc` | Совместимость флэт-конфига | Нужен, чтобы подключить `eslint-config-next` в flat config |
| `cross-env` | Переменные окружения в скриптах | Разработка ведётся на Windows: `ANALYZE=true next build` без него не запустится |

**Не понадобилось:** `web-vitals` — в Next есть встроенный `useReportWebVitals` (`PERFORMANCE.md` §3.2).

### 3.2. Корень репозитория

| Пакет | Роль | Обоснование |
|---|---|---|
| `concurrently` | Запуск обеих частей одной командой | `npm run dev` в корне поднимает `client` и `server` в одном терминале с префиксами в логах и общим `Ctrl+C`. Кросс-платформенно: `&` из Bash не работает в PowerShell, а разработка идёт на Windows |

Это единственная зависимость в корне и единственная, которая туда допускается: корневой `package.json` — оркестрация, а не место для общих пакетов. Любая зависимость приложения ставится в `client` или в `server`.

### 3.3. `server`

| Пакет | Роль | Обоснование |
|---|---|---|
| `fastify` | HTTP-фреймворк | Схемы запроса и ответа дают и валидацию, и быструю сериализацию (`fast-json-stringify`), и документируемый контракт. Встроенный `pino` закрывает структурное логирование без отдельной зависимости |
| `@fastify/cors` | CORS | Явный список источников для запросов от `client` |
| `@fastify/helmet` | Заголовки безопасности | Базовая гигиена публичного API |
| `@fastify/rate-limit` | Ограничение частоты | Публичная форма без лимита — это спам и вектор перегрузки (`server/PERFORMANCE.md` §12) |
| `zod` + `fastify-type-provider-zod` | Валидация и типы | Одно описание даёт и проверку входа, и типы контракта — без ручной синхронизации |
| `better-sqlite3` | Драйвер SQLite | Синхронный API, самое быстрое чтение среди драйверов SQLite, поддержка WAL и подготовленных выражений. Требует дисциплины (запрос блокирует поток) — правила в `server/PERFORMANCE.md` §4 и §6 |
| `nodemailer` | Отправка писем | Требование задачи; де-факто стандарт для SMTP в Node |
| `dotenv` | Переменные окружения | Явная загрузка `.env` в модуле конфигурации |
| `tsx` | Запуск TypeScript в разработке | `npm run dev` с перезапуском без отдельного шага сборки; им же запускаются тесты и миграции |
| `pino-pretty` | Читаемые логи в разработке | Только `devDependencies`; в продакшене логи остаются JSON |
| `@types/better-sqlite3`, `@types/nodemailer`, `@types/node` | Типы | Строгая типизация внешних модулей |

**Рассмотрено и отложено (кандидаты, добавляются по необходимости и по согласованию):** `@fastify/under-pressure` (метрики задержки event loop и отказ под перегрузкой), `@fastify/static` (отдача загруженных файлов, если статику не заберёт nginx), `@fastify/multipart` (загрузка файлов), `@fastify/swagger` (документация API из уже существующих схем), `@lhci/cli` (Lighthouse в CI).

**Рассмотрено и отклонено:** ORM (Prisma, Drizzle, Knex). Для нескольких таблиц контента и одной таблицы обращений подготовленные выражения в репозиториях проще, быстрее и прозрачнее; ORM добавила бы генерацию, слой абстракции и вес без выигрыша. Решение пересматривается, если схема данных вырастет.

## 4. Замечание по версиям и окружению

- Разработка ведётся на **Node 22 LTS** (`.nvmrc`). Это важно для `better-sqlite3`: у нативного модуля есть готовые сборки под LTS-версии, а на самых свежих нестабильных версиях Node установка может потребовать компилятора.
- Версии в `package.json` записаны диапазонами `^`/`~` и являются отправной точкой. Фактические версии фиксируются `package-lock.json` при первом `npm install`.
- Любая новая зависимость — отдельное решение с обоснованием веса и лицензии (`AGENTS.md` §20, п. 4). Перед установкой проверяем размер и наличие ESM/tree-shaking.
